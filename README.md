# Credit Card Fraud Detection

A Python machine-learning project for exploring transaction data, training fraud classifiers, and trying a saved classifier in a Streamlit web app.
Go Live :- https://creditcardfrauddetection-r5afrxvqdeafhbwk88mhz6.streamlit.app/

> **Important:** This is an educational demonstration, not a production fraud-detection system. The included dataset is synthetic sample data generated by this project. The notebook's current saved evaluation output is poor (43% accuracy and ROC AUC 0.398 on its holdout set). Do not rely on this model for real financial decisions.

## Project overview

The project contains a Jupyter notebook for exploratory analysis and model training, a helper that creates a sample dataset when no input CSV is available, and a Streamlit interface for testing the serialized logistic-regression pipeline.

The Streamlit app offers two ways to make predictions:

1. Enter one transaction in the form. `Time` and `Amount` are entered directly; the 28 anonymized features (`V1` through `V28`) are entered in an expandable section.
2. Upload a CSV containing all 30 model input columns. The app shows a prediction and estimated fraud probability for each row and lets you download the results.

## Dataset

The CSV uses the familiar credit-card fraud dataset column layout:

- `Time`: elapsed-time-style numeric value.
- `V1`–`V28`: anonymized numeric transaction features.
- `Amount`: transaction amount.
- `Class`: target label in the training dataset (`0` = non-fraud, `1` = fraud).

The included/generated file currently has 5,000 rows and 31 columns: 4,850 non-fraud labels and 150 fraud labels. These rows are **synthetic**, generated with NumPy; they are not the original public credit-card transaction dataset and do not represent actual customer activity. The generator uses a fixed random seed by default so its output is reproducible.

The generator creates normally distributed anonymized feature values, derives synthetic class labels from a logistic signal based on selected features, assigns integer `Time` values and log-normally distributed `Amount` values, and writes the columns in the order above.

### Use a different CSV with the notebook

The notebook checks `CREDITCARD_CSV` first when it is set, otherwise it looks for:

1. `creditcard.csv`
2. `data/creditcard.csv`
3. `datasets/creditcard.csv`

If no dataset is found, it generates one. To point the notebook at another CSV, set the environment variable before launching Jupyter:

```bash
export CREDITCARD_CSV="/path/to/your/creditcard.csv"
jupyter notebook
```

The alternate CSV must have the expected columns, including a `Class` target column, for notebook training to work.

## Machine-learning workflow

The notebook:

1. Loads the CSV and explores the rows, columns, summary statistics, and class distribution.
2. Separates `Class` from the input features.
3. Balances the data by retaining all fraud rows and randomly sampling an equal number of non-fraud rows.
4. Splits the balanced subset into training and test sets with an 80/20 split, using stratification and `random_state=42`.
5. Trains a logistic-regression pipeline using `StandardScaler` followed by `LogisticRegression(max_iter=4000)`.
6. Also trains a `RandomForestClassifier` with 100 trees for comparison.
7. Reports accuracy, confusion matrix, classification report, and ROC AUC for the logistic-regression model.
8. Saves the logistic-regression pipeline as `logistic_model.pkl`.

The notebook's current saved outputs report **43% accuracy** and **0.398 ROC AUC** for the logistic-regression model on a 60-row balanced test set. This is poor performance and is not a reliable estimate of real-world fraud detection. The balanced test set also does not reflect the natural class distribution in the generated CSV.

The app uses the saved logistic-regression pipeline, not the notebook's random-forest model. If you change the training data or model, rerun the notebook's training and export cells to recreate `logistic_model.pkl`.

## Streamlit app

The application loads `logistic_model.pkl` and obtains the expected feature names from the fitted model. Both input modes send the 30 input columns to the same pipeline and use a probability threshold of `0.5`:

- Probability at or above `0.5`: **Potential fraud**
- Probability below `0.5`: **Likely legitimate**

For CSV uploads, required input columns are `Time`, `V1`–`V28`, and `Amount`. Extra columns are retained in the displayed/downloadable result but are not passed to the classifier. If the `Class` column is included in an uploaded file, it is not used as a model input.

The CSV output includes the original columns plus `Fraud probability` and `Prediction`.

## Requirements

- Python 3.10 or newer is recommended.
- Packages are listed in `requirements.txt`: pandas, NumPy, Matplotlib, Seaborn, scikit-learn, Jupyter, and Streamlit.
- The included pickle was created with scikit-learn 1.9.1. Use the same scikit-learn version when loading it; scikit-learn does not guarantee compatibility of serialized models across versions.

## Run locally

From the repository root:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
streamlit run app.py
```

On Windows PowerShell, activate the environment with:

```powershell
.\.venv\Scripts\Activate.ps1
```

Streamlit prints a local URL (usually `http://localhost:8501`) in the terminal. Open it in a browser. In GitHub Codespaces, open the forwarded port `8501` from the **Ports** panel.

If `logistic_model.pkl` is missing, run the notebook's training and model-export cells first; the app intentionally reports an error rather than silently creating or substituting a model.

## Run the notebook

With the virtual environment active and dependencies installed:

```bash
jupyter notebook
```

Open `FraudDetection.ipynb` and run the cells from top to bottom. If no input dataset is present, the notebook imports `generate_creditcard_dataset.py` to create the synthetic sample CSV automatically.

To generate the CSV without opening the notebook:

```bash
python generate_creditcard_dataset.py
```

This writes `creditcard.csv` in the current working directory. By default, it creates 5,000 rows with random seed 42.

## Deploy on Streamlit Community Cloud

1. Push the project to a GitHub repository.
2. Ensure the repository contains `app.py`, `logistic_model.pkl`, and `requirements.txt`. The app does not require the CSV files at runtime.
3. Open [Streamlit Community Cloud](https://share.streamlit.io/) and sign in with GitHub.
4. Select **Create app**, choose the repository and branch, and set the app's main file path to `app.py`.
5. Deploy the app.

Keep the model artifact and the training scikit-learn version compatible. If the dependency version in `requirements.txt` changes, retrain/re-export the model in that version or set the deployment dependency to the version used to create the pickle.

## Troubleshooting

### `ModuleNotFoundError: No module named 'streamlit'`

Activate the intended virtual environment and run:

```bash
python -m pip install -r requirements.txt
```

### `Model file not found`

Make sure `logistic_model.pkl` is present alongside `app.py`. To recreate it, run the notebook through the model-export cell after training.

### Uploaded CSV is missing required model columns

Include all of these exact, case-sensitive headers:

```text
Time,V1,V2,V3,V4,V5,V6,V7,V8,V9,V10,V11,V12,V13,V14,V15,V16,V17,V18,V19,V20,V21,V22,V23,V24,V25,V26,V27,V28,Amount
```

Each row must contain numeric values for the required features.

### Pickle or scikit-learn compatibility error

Install the scikit-learn version used to save the artifact, or recreate the artifact with the version installed in the deployment environment. Only load pickle files from a trusted source.

## Limitations and safety

- The included data is synthetic and intentionally not a substitute for a validated public or production dataset.
- The notebook balances classes by undersampling non-fraud transactions. This discards much of the available majority-class data and changes the class distribution used for evaluation.
- The saved evaluation performance is weak; predictions should be treated as demonstrations of the interface only.
- The app's `0.5` threshold is fixed and has not been selected using a production cost/benefit analysis.
- Real deployments need representative validated data, leakage-aware validation, threshold tuning, calibration, monitoring, privacy controls, and review by qualified domain experts.
- A scikit-learn pickle can execute code when loaded. Do not replace `logistic_model.pkl` with a file from an untrusted source.
